# 눈 깜빡임 알림 프로토타입

현재 버전: **07** (`VERSION` 파일 기준). 이후 수정 사항을 커밋할 때마다 버전을 `07`, `08`처럼 1씩 올리고, 커밋 메시지에 변경 내용과 이유를 적습니다. 각 버전은 같은 번호의 Git 태그(`v00`, `v01` 등)로 표시합니다.

Windows에서 `run.cmd`를 실행하면 최근 60초 측정값과 일일 통계가 한 창에 열립니다. 날짜를 선택하고 그래프의 점이나 선을 클릭하면 해당 5분 구간의 분당 깜빡임 횟수가 표시됩니다. 유효 측정 기록이 없는 구간에서는 선이 끊깁니다.

날짜별 통계 CSV는 `%LOCALAPPDATA%\BlinkReminder\logs\blink_YYYY-MM-DD.csv`에 저장합니다. 같은 날 실행한 세션을 이어 쓰고, PC 시계의 분 경계와 종료 시점에 기록합니다. `--no-csv`는 날짜별 통계와 프레임별 기록을 끕니다. `--csv-dir`은 프레임별 기록 폴더를 지정합니다.

기본 창의 **설정**에서 분당 알림 기준과 알림 방식을 바꾸고 **알림 확인**으로 시험할 수 있습니다. **자동 알림** 메뉴에서 10분, 1시간, 2시간, 24시간 또는 **계속 끄기**를 선택합니다. 타이머가 끝나거나 **알림 켜기**를 선택하면 자동 알림이 다시 켜집니다. 앱을 재실행해도 선택을 유지하며 알림을 끈 동안 측정과 기록은 계속됩니다. **일일 통계 → CSV 내보내기**는 선택한 날짜의 CSV를 다른 경로에 복사합니다.

**오늘 요약**은 PC의 오늘 날짜에 저장된 모든 세션의 유효 측정 시간, 깜빡임 총횟수, 분당 깜빡임, 표시된 자동 알림을 보여줍니다. 그래프에서 다른 날짜를 골라도 오늘 요약은 오늘 데이터를 표시합니다. 오늘 CSV를 저장하면 값이 갱신되고, 유효 측정 시간이 0이면 **측정 기록 없음**을 표시합니다.

손이 눈을 가리거나 양쪽 눈을 모두 확인하기 어려우면 **눈 확인 안 됨 · 측정 대기**가 표시됩니다. 이 구간은 유효 측정 시간에서 제외되며 눈이 다시 관측되면 측정이 재개됩니다.

v01은 무효 EAR 방어 처리, 눈 좌표·FPS·CSV 기록, 키/마우스 조작과 검증 기록을 포함합니다. 보수형 빠른 연속 깜빡임 판정은 `run-validation.cmd` 또는 `run-ui.vbs`에서 사용할 수 있습니다. 현재 진행 상태는 [개발관리/STATUS.md](개발관리/STATUS.md)를 참고하세요. 실제 웹캠 원본 CSV·JSON과 후보의 프레임별 재생 기록은 로컬에 보관하고 저장소에는 소스·요약·합성 검증 자료를 포함합니다.

웹캠 영상은 Python과 MediaPipe가 읽고, **깜빡임 판정·최근 60초 집계·알림 결정은 C**가 처리합니다. 얼굴 영상은 저장하지 않습니다. 기본 기준인 12회/60초는 시연용 설정이며 의학적 기준이 아닙니다.

## 작업 순서와 현재 상태

1. **최소 기능 구현 완료**: 얼굴의 양쪽 눈 EAR 계산 → C 라이브러리 호출 → 60초 집계 → 👀 알림.
2. **판정 안정화 완료**: 연속 2프레임, 양쪽 눈 일치, 얼굴 미검출 시간 제외, 알림 대기 시간.
3. **현장 조정**: 조명·카메라에 따라 `--closed-ear`, `--open-ear`, 기준 횟수를 조정하고 실제 사람의 수기 기록과 비교.
4. **발표**: 아래 C 상태 변수, 배열, 조건문, 시간 계산을 실행 화면과 함께 설명.

## 실행

Windows 기준, 이 폴더에서 다음을 순서대로 실행합니다. 얼굴 또는 손 랜드마크 모델이 없는 경우 처음 실행할 때 Google에서 내려받습니다. 두 모델은 `models` 폴더에 보관합니다.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe build.py
.\run.cmd --min-blinks 12
```

영상 창을 클릭하고 영문 입력 상태에서 `Q`/`q` 또는 `Esc`로 종료하고, `+`/`-`로 기준 횟수, `L`/`l`로 눈 좌표 표시를 바꿀 수 있습니다. 마우스로 영상 아래 **Points ON/OFF**를 누르면 좌표 표시를 전환하고 **Exit** 또는 창의 **X**로 종료할 수도 있습니다. 다른 카메라는 `--camera 1`처럼 지정합니다. 모델을 직접 받은 경우 `--model 경로`로 지정할 수 있습니다. 팝업을 표시하지 못하는 환경에서는 콘솔에 같은 알림이 출력됩니다.

## 좌표·FPS·수치 기록 확인

기본 창에서 **카메라 미리보기**를 켜면 EAR 계산에 쓰는 양쪽 눈의 12개 좌표와 FPS가 표시되고 수치 기록을 자동 저장합니다. FPS는 약 최근 1초간 실제 처리된 프레임 간격으로 계산하며 첫 프레임은 `--`입니다. 카메라 설정 FPS나 검출 정확도를 뜻하지 않습니다.

- 저장 위치: 프로젝트의 `data/records/blink_날짜_시각.csv`. 같은 이름의 `.json`에는 시작 설정·소스 및 C 라이브러리 해시가 저장됩니다.
- CSV는 각 처리 프레임의 시각·경과 시간·유효 측정 시간·프레임 간격·FPS·얼굴 검출·측정 유효성·좌우 EAR·눈 상태·깜빡임 이벤트·최근 60초 횟수·알림·판정 설정·좌표 표시 여부를 기록합니다. 얼굴 영상은 저장하지 않습니다.
- `face_detected`는 얼굴 검출, `measurement_valid`는 EAR까지 유효한 관측입니다. 미검출 EAR 칸은 비우며, 검출됐으나 무효한 값은 `nan`/`inf` 등 원래 값을 남깁니다. `eye_state`는 0=확인 중, 1=열림, 2=감김입니다.
- `frame_interval_ms`, `monotonic_ms`, `elapsed_ms`, `active_ms`, `low_for_ms`의 단위는 ms, `fps`는 프레임/초, `target`·`count_60s`는 회입니다. `low_seconds`·`cooldown_seconds`는 초이며 EAR은 무차원 비율입니다.
- `local_time`은 PC 시간대 오프셋을 포함한 프레임 입력 시각입니다. `elapsed_ms`는 첫 프레임 이후 실제 경과 시간, `active_ms`는 C가 인정한 유효 시간입니다. `monotonic_ms`는 C 입력 시각으로 세션 간 절대 시각 비교에는 사용하지 않습니다.
- `blink=1`인 행이 개별 검출 이벤트입니다. 빠른 연속 동작은 이 행과 EAR·프레임 간격을 비교하세요. `count_60s`는 오래된 이벤트 만료로 감소할 수 있습니다.
- `landmarks_visible`은 좌표 표시 옵션이 켜져 있는지를 기록합니다. 실제 점은 얼굴과 EAR이 유효한 프레임에서만 그립니다.
- 정상 종료 시 파일을 마무리하고 실행 중 약 1초마다 버퍼를 비웁니다. 종료한 뒤 Excel 등으로 여세요. 저장 오류는 콘솔과 화면 `CSV: ERROR`로 알리며 측정·알림은 계속합니다.

좌표를 끄고 시작하려면 `run.cmd --no-landmarks`, 기록 없이 실행하려면 `run.cmd --no-csv`, 저장 위치를 바꾸려면 `run.cmd --csv-dir "저장할 폴더"`를 사용합니다. 기본 키·알림과 C 판정 규칙은 유지합니다.

설치가 끝난 이 PC에서는 PowerShell을 **어느 폴더에서 열어도** 다음 명령으로 실행할 수 있습니다. `run.cmd`가 프로젝트 폴더로 이동한 뒤 프로그램을 시작합니다.

```powershell
& 'C:\Users\alex6\Desktop\프기2_조별과제\run.cmd'
```

프로그램 화면에 초점을 맞춘 뒤 `Q` 또는 `Esc`를 누르면 종료됩니다. 이 PC에서는 일반 실행 권한의 PowerShell로 실제 카메라 프레임과 깜빡임 집계를 확인했습니다. 카메라가 없다는 메시지가 **Codex의 제한된 도구 실행 환경에서만** 나타날 수 있으므로, 그 경우 일반 Windows PowerShell에서 위 명령을 사용하세요.

```powershell
.\.venv\Scripts\python.exe blink_app.py --min-blinks 8 --closed-ear 0.17 --open-ear 0.22 --low-seconds 10 --cooldown 60
```

`EAR`은 눈의 세로 길이 합을 가로 길이의 두 배로 나눈 값입니다. 눈을 뜨면 높고 감으면 낮아집니다. 화면의 `EAR L/R`를 보고 자신의 눈에 맞는 두 문턱값을 정하세요. `closed-ear`는 감김의 상한, `open-ear`는 열림의 하한이며, 두 값 사이에서는 상태를 바꾸지 않습니다.

## 단계별 확인

1. `.\.venv\Scripts\python.exe -m unittest test_engine.py test_invalid_ear.py test_measurement_log.py -v`로 자동 검증합니다. 열린 눈→감긴 눈→열린 눈은 1회, 감긴 동안 중복 집계 없음, 한 프레임 잡음 제외, 무효 입력 처리와 CSV 연결을 확인합니다. 기록 연결 테스트는 실제 C와 합성 영상·모의 검출기를 사용하며 실제 웹캠 테스트와 구분합니다.
2. 카메라 화면에서 얼굴을 보이면 `Eyes`와 양쪽 `EAR`이 나오며, 한 번 깜빡일 때 `60s blinks`가 1씩 증가하는지 봅니다. 얼굴을 가리면 `NO FACE`가 표시됩니다.
3. 빠른 시연은 `--min-blinks 1 --low-seconds 0 --cooldown 10`으로 실행합니다. **얼굴이 보인 누적 시간 60초**가 지난 뒤 깜빡임이 0회라면 작은 👀 알림이 뜹니다. 알림 후 10초 이내에는 다시 뜨지 않습니다.

## C 코드 설명

- `state`는 `UNKNOWN(0)`, `OPEN(1)`, `CLOSED(2)` 중 하나입니다. 시작할 때 열린 상태를 두 프레임 확인해야 합니다.
- `candidate_frames`는 같은 상태가 연속으로 들어온 횟수입니다. 양쪽 눈이 다르거나 문턱값 사이면 후보를 지워 순간 오류를 무시합니다.
- `if (state == CLOSED && candidate == OPEN)`에서 **감김 뒤 열림**을 한 번만 셉니다. 감긴 동안은 상태가 그대로라 중복되지 않습니다.
- `events[]` 배열에는 각 깜빡임의 `active_ms`를 저장합니다. `prune()`은 60초보다 오래된 시각을 제거하고 `event_count`가 최근 횟수입니다.
- `active_ms`는 얼굴이 연속으로 보이고 양쪽 EAR이 유효한 프레임의 시간차만 더합니다. 얼굴 미검출·무효 EAR(NaN, 무한대, 음수)·1초 넘는 프레임 공백은 집계 시간에 넣지 않습니다. 무효 EAR은 눈 상태를 초기화하고 알림을 멈추며, 기존 집계 기록은 유지합니다. 정상 복귀 후 열린 눈을 다시 확인한 뒤 새 깜빡임부터 셉니다.
- 최근 횟수가 `target`보다 낮은 상태가 `low_duration_ms` 이상 이어지면 `alert=1`을 반환합니다. `last_alert_ms`와 `cooldown_ms`가 연속 알림을 막습니다.
- Python의 `engine.py`는 `ctypes`로 C 함수를 호출하고, `blink_app.py`는 입력 영상과 알림 UI만 담당합니다.
