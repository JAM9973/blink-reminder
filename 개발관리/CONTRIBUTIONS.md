# 실제 작업과 개인 기여 기록

## 과제의 부분주제와 실제 작업 방식

- 조재민: 입력·인식. Python 영상 입력, 눈 좌표·EAR, C 전달, 인식 조건 비교.
- 김재원: C 판정·집계·알림. 깜빡임 상태 전이, 60초 집계, 알림 결정, 기본 알림·설정·일시정지 보완.
- 실제 개발 방식: 조재민이 두 영역의 전체 코드를 통합 구현한다. 김재원이 수행하는 검토·실험·수정 활동은 실제 수행 후 별도로 기록한다.
- 개발 환경: WSL Ubuntu. 최종 실행·카메라·UI 검증: Windows.

파일·함수의 기능 영역과 실제 작성자를 구분한다. blink_app.py의 입력 처리·EyeNotice 알림, C 판정 등 실제 수정한 파일·함수를 턴별로 기록한다. engine.py와 blink_engine.h를 바꾸는 턴에는 양쪽 연동 확인을 남긴다.

현재 공통 기반 코드는 존재하지만 과거의 개인 작성 내역은 이 표로 증명되지 않는다. 기존 코드 검토, 직접 수정, 테스트 설계·실행, 실험·분석, 통합 작업을 구체적으로 기록한다.

## 진행률 계산 제안

현재 구현 방식에서는 아래 이전 부분주제별 배점표를 개인별 완료율로 바로 사용하지 않는다. 실제 담당 작업을 확인한 뒤 구현·검증·사용성·재현 확인 항목으로 나누고 완료 근거에 따라 계산한다. 계산값에 맞추려고 기능을 삭제하거나 완료 상태를 바꾸지 않는다.

`개인 진행률 = 완료한 담당 작업의 가중치 합 / 전체 담당 작업의 가중치 합 × 100`

부분 완료는 작업을 확인 가능한 하위 항목으로 나눠 계산한다. 각 완료 항목에는 관련 코드와 확인 결과를 연결한다. 공동 작업의 개인 기여는 각자 수행한 활동을 적는다.

### 이전 입력·인식 부분주제의 배점 예시 — 현재 완료율이 아님

| 담당 작업 | 가중치 초안 | 중간 제출 목표 | 실제 완료 근거 |
|---|---:|---|---|
| 웹캠·얼굴 검출 기본 실행 | 10 | 확인 완료 목표 | 제출 전 작성 |
| 눈 좌표·EAR 계산 | 20 | 확인 완료 목표 | 제출 전 작성 |
| C 입력 연동·기본 상태 표시 | 10 | 확인 완료 목표 | 제출 전 작성 |
| 좌표 확인·기초 기록 기능 | 10 | 확인 완료 목표 | 제출 전 작성 |
| 조명·안경·각도별 인식 비교·개선 | 25 | 최종까지 진행 | 제출 전 작성 |
| 처리 속도·예외 상황·지속 실행 | 15 | 최종까지 진행 | 제출 전 작성 |
| 다른 환경 실행·입력 모듈 설명 | 10 | 최종까지 진행 | 제출 전 작성 |

### 이전 판정·알림 부분주제의 배점 예시 — 현재 완료율이 아님

| 담당 작업 | 가중치 초안 | 중간 제출 목표 | 실제 완료 근거 |
|---|---:|---|---|
| 눈 상태 전이·1회 집계 | 20 | 확인 완료 목표 | 제출 전 작성 |
| 최근 60초 기록 관리 | 15 | 확인 완료 목표 | 제출 전 작성 |
| 기준 미달·재알림 간격·기본 알림 | 15 | 확인 완료 목표 | 제출 전 작성 |
| 경계 상황·판정 오류 회귀 검증 | 15 | 중간부터 최종까지 진행 | 제출 전 작성 |
| 실제 오탐·누락 분석과 개선 | 20 | 최종까지 진행 | 제출 전 작성 |
| 설정·일시정지·알림 사용성·재현 확인 | 15 | 최종까지 진행 | 제출 전 작성 |

두 표는 기능 영역별 작업량을 생각하기 위한 이전 예시다. 조재민이 전체를 구현하는 현재 방식에서 이 예시를 두 사람의 개인 진행률로 복사하지 않는다. 개인 제출은 각자가 실제로 수행한 활동과 전체 담당 범위를 기준으로 작성한다.
