# Codex CLI에서 사용할 턴별 프롬프트

아래 지시문은 앞으로 사용할 템플릿이다. 실행한 프롬프트의 이력이 아니다. 프로젝트 루트에서 CLI를 사용하고 AGENTS.md의 공통 지침을 적용한다. PLAN·STATUS 등의 관리 문서는 프롬프트에서 직접 읽도록 지정한다.

환경은 WSL Ubuntu에서 개발하고 Windows에서 최종 실행하는 구성이다. 조재민이 전체 구현을 진행한다. WSL의 가상 입력 테스트와 Windows의 웹캠·UI 검증 결과를 구분한다.

최신 진행: T08-A 후보 비교 완료. 아래 T08-A 템플릿은 재현용이며 다음 작업은 RAPID_BLINK_PLAN과 최신 STATUS의 T08-B 범위를 따른다. 보수형 후보의 빠른 기록 8회는 목표 10회에 미달한 중간 결과이고 현재 앱에는 미적용이다.

## 11/3 현황 기준 다음 턴: T01 남은 작업

최신 우선순위는 아래 T08-A다. 이 T01 템플릿은 WSL 환경 확인의 남은 작업을 재개할 때 사용하며 현재 진행 위치를 뜻하지 않는다.

```text
AGENTS.md와 개발관리/README.md, PLAN.md, STATUS.md, WSL_WINDOWS_GUIDE.md를 읽고
T01의 남은 환경 확인과 기준 버전 확보만 진행해줘.
Windows에서는 11/3 DLL 빌드와 기존 테스트 5개가 통과했어. 빌드 실패를 현재 상태로 가정하지 마.
Git의 기존 수정·새 파일을 보존하고 clone/archive에서 누락되지 않게 전달 목록을 확인해줘.
WSL 조회는 E_ACCESSDENIED였어. 접근 가능한 환경에서 버전·아키텍처·빌드·테스트를 확인하고,
접근할 수 없다면 독립적으로 가능한 Windows 검증을 계속하고 WSL은 미확인으로 남겨줘.
Windows 웹캠·기본 알림을 실제 재확인하고, 못 했으면 직접 확인할 절차를 남겨줘.
camera_worker.py와 app_settings.py는 실행 경로에 미연결이야. 확장 UI를 한꺼번에 구현하지 마.
현재 기준 버전 보존 방법과 실제 결과를 기록해줘. 커밋 시 기존 VERSION·태그 규칙을 지켜줘.
STATUS.md·DEVELOPMENT_LOG.md를 갱신하고 T02는 자동 시작하지 마.
```

아래 기존 템플릿은 최신 PLAN·STATUS를 우선해 사용한다. T02·T04·T09·T10에서는 확장 소스의 필요한 부분을 재사용하고 미연결 코드를 완료 기능으로 취급하지 않는다.

## 다음 구현: T08-A 빠른 연속 깜빡임 후보 비교

```text
AGENTS.md, 개발관리/README.md, PLAN.md, STATUS.md, RAPID_BLINK_PLAN.md를 읽고 T08-A만 진행해줘.
빠른 두 번 5묶음은 실제 10회이며 기존 검출은 5회야. 평소 기록은 실제/검출 모두 10회야.
기존 변경과 원본 CSV·설정·코드 버전을 보존하고 앱 밖의 작업본에서 판정 후보를 비교해줘.
단순 문턱값/프레임 변경 대조안과 양쪽 EAR의 상대 상승·재하강을 확인하는 안을 검토해줘.
현재 두 CSV의 같은 입력을 재생하고 개별 이벤트·파형·시각과 부작용을 비교해줘.
긴 감김의 출렁임·한쪽 눈·무효 값·미검출·중복 이벤트 등 계획의 반례와 기존 회귀를 확인해줘.
총횟수 10에만 맞추지 말고 근거가 부족한 구간은 구분 불가로 남겨줘.
현재 앱의 기본 판정·UI·CSV를 바꾸지 말고 후보별 결과·선택안·단점을 기록한 뒤 멈춰줘.
아직 실제로 수행하지 않은 개선율·오탐/누락률·새 웹캠 결과는 쓰지 마.
STATUS.md·DEVELOPMENT_LOG.md를 실제 결과로 갱신하고 T08-B는 자동 시작하지 마.
```

## 첫 구현: T01 WSL 개발·Windows 실행 기반

```text
AGENTS.md와 개발관리/PLAN.md, STATUS.md를 읽고 T01만 진행해줘.
개발관리/WSL_WINDOWS_GUIDE.md도 참고해줘.
나는 조재민이고 실제 전체 구현은 내가 진행해. 개발은 WSL Ubuntu, 최종 실행은 Windows야.
먼저 Ubuntu·WSL 버전, CPU 아키텍처, Python·C 컴파일러·Git·Codex 경로와 버전을 확인해줘.
build.py, test_engine.py, blink_engine.c, blink_engine.h, engine.py를 읽고,
WSL의 별도 Python 가상환경에서 C 빌드·가상 입력 테스트를 실행할 수 있게 해줘.
Windows용 Python 가상환경과 C DLL은 별도로 준비하는 방식으로 구성해줘.
기존에 기록된 빌드 실패는 Windows에서 관찰한 것이므로 WSL에서도 같은 원인이라고 가정하지 마.
필요한 최소 수정으로 플랫폼별 빌드와 경로 처리를 보완하고 실제 확인한 원인만 설명해줘.
완료 기준은 WSL의 빌드·기초 테스트 결과, Windows 네이티브 빌드·테스트·웹캠 실행 절차야.
Windows의 Python·컴파일러 아키텍처와 영상 처리 의존성도 확인할 수 있는 명령을 제공해줘.
Windows 확인을 직접 수행할 수 없으면 사용자가 실행할 명령과 기대 결과를 정리하고 미검증으로 남겨줘.
WSL 카메라 연결이나 Linux용 알림 UI 확장은 이번 턴의 목표에 넣지 마.
STATUS.md와 DEVELOPMENT_LOG.md에 실제 프롬프트·수정 이유·환경별 결과를 남겨줘.
커밋 전에는 이번 턴의 변경 파일을 검토하고 기존 VERSION·태그 규칙에 따라 로컬 체크포인트를 남겨줘.
GitHub 연결은 완성 후 진행할 예정이야.
T02는 자동으로 시작하지 말고 이번 결과와 다음 턴의 작업을 알려줘.
```

확인한 사실, 아직 검증하지 못한 항목, 사용자가 수행할 실험을 구분해줘.
