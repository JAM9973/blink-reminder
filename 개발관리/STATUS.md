### 좌표·CSV·FPS 연결 — 최신 구현 결과

- 최신 사용자 확인: L을 눌러 눈을 잘 추적하는 것을 확인했고 기록도 제대로 저장됐다고 보고. 첨부 화면에 CSV/JSON 두 쌍 표시. 키 누락의 완전 해소나 마우스 버튼 확인까지 의미하지는 않음.

- 최신 세션 blink_20261103_113457_760119.csv는 경과 71.183초·유효 61.642초·기록 FPS 중앙값 29.48프레임/초. 이는 해당 파일의 처리 기록이며 정확도 수치가 아님. 최신 JSON의 소스 해시는 현재 앱·기록기·C/헤더·브리지와 모두 일치. 첫 세션의 앱 소스 해시는 현재와 다름을 구분함.
- 근거는 [사용자 기록 구조 점검](검증결과/2026-11-03/좌표_CSV_FPS/user_record_check.json). 수기 정답·실험 동작 시점은 없어 실제 오탐·누락·빠른 두 번의 원인을 확정하지 않음.

- 후속 사용자 보고: L/Q 키 입력이 간헐적으로 씹힘. 초점·IME·처리 지연 중 원인은 아직 미확정. 코드에서 대문자 Q 미지원은 확인해 수정했으며 L은 원래 양쪽 대소문자 지원이었음.

- 자동 검증은 후속 총 24개 통과·종료 코드 0. 대문자 Q/Esc/창 닫기 및 키 이벤트 없이 마우스만으로 좌표 전환·종료·CSV 마무리를 합성 입력으로 확인. 실제 키 누락 원인의 재현·실제 마우스 조작은 사용자 확인 대기.

- 사용자 ‘다음 구현 진행해줘’ 요청으로 현재 run.cmd → blink_app.py에 눈 좌표·CSV·FPS를 연결. 눈 주변 12개 점 기본 표시, L 전환, FPS·CSV 상태 표시. CSV는 data/records 자동 저장, --no-csv·--no-landmarks·--csv-dir 지원.
- 프레임 시각·간격·FPS·경과/유효 시간·얼굴 검출/관측 유효성·좌우 EAR·C 상태/이벤트/최근 횟수/알림·판정 설정을 기록. JSON에는 시작 설정·소스/DLL 해시 저장. 숫자 기록이며 영상은 저장하지 않음.

### 무효 EAR 처리 보완 및 재검증 — 최신 결과

- 후속 사용자 확인: 안내한 얼굴 미검출·복귀 점검이 정상적으로 작동한다고 보고함. 해당 절차의 NO FACE 중 시간·횟수 유지와 새 알림 억제, 복귀 자체의 오집계 방지 및 이후 정상 집계를 사용자 실행 확인으로 기록. 개별 시각·수치·연속 로그는 제공되지 않았으므로 정량 측정 결과로 사용하지 않음.

- 수정 후 사용자 Windows 실행 보고: 평소 깜빡임은 집계되고 알림도 발생. 첨부 화면에서 기준 23회·최근 15회·유효 시간 152초와 기본 팝업 확인. 이는 사용자 보고·화면 근거이며 에이전트 직접 카메라 검증이 아님.
- 사용자 추가 관찰: 빠른 두 번의 깜빡임이 한 번으로 집계됨. 중간 열림을 2프레임 확보하지 못하면 합산될 수 있는 기존 한계와 부합하나, 실제 EAR·FPS·이벤트 시점 기록이 없어 원인은 미확정. 최근 60초 표시에서는 이전 기록의 만료도 동시에 일어나므로 이벤트 로그와 수기를 대응해 확인해야 함. 두 번을 한 번으로 세는 것을 목표 동작으로 승인한 것은 아님.
- 가림 화면: 부분 가림에서 NO FACE·Observed 82초인 장면, 다른 가림 위치에서 OPEN·Observed 86초인 장면 확인. 손으로 가린 비율 자체가 정지 기준은 아니며 얼굴 검출 및 EAR 유효성으로 결정. 정지 지속 시간·복귀 직후 오집계는 연속 기록 없이 확정하지 않음.
- 사용자 확인 절차: 얼굴 전체가 웹캠 밖으로 나가거나 렌즈를 완전히 가린 상태로 5초 유지해 NO FACE와 Observed 고정을 확인하고, 복귀 후 시간 재개·복귀 자체의 추가 집계 여부 확인. 후속 사용자 보고로 정상 동작 확인, 정량 로그는 미제공.
- 최종 사용 방식: 사용자 요청에 따라 미리보기·콘솔을 숨겨도 측정·알림 유지, 트레이에서 상태·설정·일시정지·종료 가능하게 하는 백그라운드 동작을 최종 UI 범위로 명시. 현재 구현 완료가 아니며 PLAN의 T10~T11에서 구현·검증 예정.

- 사용자 승인 규칙에 따라 C에서 한쪽이라도 NaN·무한대·음수인 EAR을 미검출에 준해 처리. 시간·알림 중단, 눈 상태 초기화, 기존 기록 보존, 복귀 후 OPEN 재확인. 0과 낮은 유효 EAR은 유지.
