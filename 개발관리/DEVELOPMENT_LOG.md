# 실제 개발 기록

## 2026-11-25 v05 손과 눈 영역의 겹침을 확인

- 사용자가 실제 손 가림 중에도 유효 시간이 증가한다고 보고했다. 기존 영상 밝기 경계는 손가락이나 손바닥의 경계에도 반응할 수 있다. 얼굴이 검출되고 EAR이 유효한 프레임에서 같은 영상 시각으로 MediaPipe Hand Landmarker를 실행한다. 한쪽 눈 검사 영역의 20% 이상이 손 영역과 겹치면 기존 C 무효 입력 경로로 보낸다.
- 손바닥은 손 관절의 외곽으로, 손가락은 관절 연결과 손바닥 너비로 근사한다. 손 위치는 영상 평면에서 비교한다. 모델은 `models/hand_landmarker.task`로 불러오며 처음에 없는 경우 다운로드한다.
- 손 모형 좌표를 넣은 앱 회귀 테스트로 얼굴과 EAR이 정상이어도 손이 눈을 가리면 측정 시간·깜빡임·알림이 집계되지 않는 것을 확인했다. Windows 실제 모델 사진 시험에서 이마·턱 근처의 손과 눈 앞에 합성한 손을 비교했다. 현장 웹캠 검증과 처리 FPS 측정은 이번에 수행하지 않았다.

## 2026-11-25 눈 영역 관측 확인을 유효 측정에 연결

- 현재 Face Landmarker 모델은 시험 사진의 눈 점에 `visibility`를 제공하지 않았다. 좌표가 정상이어도 실제 눈을 확인할 수 있도록 양쪽 눈의 화면 경계·픽셀 너비·눈꺼풀 방향의 밝기 경계를 확인하는 단계를 `input_tracking.py`에 추가했다. 눈을 감았을 때도 눈꺼풀 경계가 보이면 기존 EAR 판정을 사용한다.
- 관측에 실패한 프레임은 기존 C 무효 입력 경로로 보낸다. 프레임별 검증 CSV는 얼굴 검출·EAR과 측정 유효성을 따로 유지한다. 가림을 제거했을 때 이전 감김 상태와 연결해 집계하지 않는다.
- Windows 자동테스트 68개 통과. 한쪽 눈 가림을 모의한 앱 테스트에서 얼굴 검출과 EAR은 남았고 유효 시간과 깜빡임은 늘지 않았다. Windows 실제 모델에는 설치된 scikit-image의 얼굴 사진에 단색 가림을 적용해 한쪽·양쪽 가림과 복귀를 검증했다. 웹캠에서는 시험 중 얼굴이 검출되지 않아, 실제 손 가림·저조도·안경 조건에 대한 성능은 확인하지 못했다.

## 2026-11-25 v04 오늘 요약

- `daily_log.py`에서 CSV의 모든 세션을 합산해 유효 시간, 개별 깜빡임, 표시된 자동 알림을 계산한다. 깜빡임 총횟수에 60을 곱한 뒤 유효 초로 나눠 분당 값을 계산한다. 시간은 소수 셋째 자리, 분당 값은 소수 둘째 자리로 표시한다.
- 날짜별 그래프와 요약이 같은 CSV 판독 코드를 사용한다. 화면을 열거나 앱에서 새 CSV 행을 저장하면 PC의 오늘 날짜를 읽고, 창이 열린 채 PC 날짜가 바뀌어도 오늘 요약을 갱신한다. 통계 화면과 판정·CSV 저장을 연결하는 기존 갱신 경로를 사용했다.
- Windows 자동테스트 67개, WSL C 판정·CSV·오늘 요약 테스트 12개를 통과했다. 합성 테스트로 오늘·어제 데이터 분리, 여러 세션 합산과 유효 시간이 0일 때의 처리를 검증했다.
- Windows 내장 웹캠으로 약 75초 실행했다. 초기 오늘 요약은 **측정 기록 없음**이었다. 어제 그래프 선택 상태에서 첫 저장 후 오늘 CSV와 요약이 56.735초·15회·15.86회/분·표시 알림 0회로 일치했다. 정상 종료 후 창을 다시 열었을 때는 74.097초·18회·14.58회/분·표시 알림 1회로 일치했다. 별도 Windows 창에서 날짜 전환을 모의해 새 CSV 저장이 없어도 다음 날짜의 빈 상태가 표시되는 것을 확인했다.

## 2026-11-25 v03 자동 알림 끄기와 날짜별 CSV 내보내기

- 자동 알림 끄기 종료 시각과 계속 끄기 상태를 사용자 폴더의 `notification_mute.json`에 저장한다. 시간이 끝나면 정상 알림 판정을 다시 표시한다. 억제 중 경고를 쌓아 두지 않으며, **알림 확인**은 수동 미리보기로 사용할 수 있다.
- 선택 날짜 CSV를 읽는 동안 기존 기록 잠금을 사용하고 내보내기 대상에는 임시 파일을 복사한 뒤 교체한다. 앱이 기록하는 날짜별 CSV와 잠금 파일을 내보내기 경로로 지정할 수 없다.
- Windows UI에서 선택한 이전 날짜 CSV의 바이트가 내보낸 파일과 같은 것을 확인했다. Windows 자동테스트 66개와 WSL C 판정·CSV 테스트 11개를 통과했다. 첫 Windows 자동테스트의 실행 옵션 오류를 수정한 뒤 전체 테스트를 다시 실행했다.
- Windows 내장 웹캠으로 10분 옵션의 상태 표시와 타이머 자동 복귀를 확인했다. 종료 시각을 앞당겨 약 80초간 검증했고, 유효 측정 79.376초 동안 발생한 C 알림은 만료 전 억제 5회, 만료 후 표시 5회였다. 날짜별 CSV에는 표시 5회만 기록됐다. 첫 웹캠 검증의 비교 단계는 프레임 CSV의 UTF-8 BOM 때문에 실패했고, 인코딩을 바로잡아 재실행했다.

## 2026-11-25 v02 날짜별 CSV와 일일 통계

- `app_runtime.py`에서 C가 보고한 개별 깜빡임, C 유효 시간의 증가량, 표시가 성공한 자동 알림을 일일 집계에 전달한다. 일시정지·유효하지 않은 EAR·추적이 장시간 끊긴 구간은 C 유효 시간에서 제외한다. 수동 알림 확인은 통계에 포함하지 않는다.
- `daily_log.py`가 시계의 분 경계에서 유효 시간을 나누고, 자정 이후에는 새 날짜 파일에 저장한다. 하루의 모든 세션을 5분 단위로 합산하는 통계를 Windows 기본 창에 연결했다. 프레임별 CSV 열과 기록 경로는 기존과 같다.
- Windows DLL을 x64로 다시 빌드하고 자동테스트 63개를 통과했다. WSL Ubuntu 26.04 ARM64 빌드와 자동테스트 10개를 통과했다. WSL의 첫 시도는 일일 집계 단위 테스트가 불필요하게 Pillow를 불러 실패했고, 집계 테스트의 앱 의존성을 분리한 뒤 재실행했다.
- 내장 웹캠으로 두 번 실행한 뒤 검증용 CSV에서 같은 날짜에 세션 두 개가 이어 붙는 것을 확인했다. Windows에서 날짜 전환·그래프·0점 표시·미측정 구간을 확인했다. 개인 측정 CSV는 커밋에서 제외한다.
- 내장 웹캠을 80초 실행해 C 자동 알림 1회가 Windows에 표시되고 날짜별 CSV에도 1회로 기록된 것을 확인했다. 한 세션의 유효 시간 79.276초가 시계의 분 경계에서 2행으로 나뉘었다. 알림 검증에만 60초당 1,000회와 기준 미달 지속 시간 0초를 사용했다.

이 문서는 수행한 작업만 기록한다. 향후 프롬프트는 PROMPTS.md, 예정 작업은 PLAN.md에 있다.
