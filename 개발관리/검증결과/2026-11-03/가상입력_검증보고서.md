# 현재 규칙은 통과했고, 무효 EAR 처리에서 보완점이 재현됐다

이 문서는 **수정 전 검증 기록**이다. 후속 수정 및 같은 입력의 재검증 결과는 [수정 전후 보고서](무효_EAR_보완/수정_전후_검증보고서.md)를 참고한다. 아래 값과 원본 로그는 수정 전 근거로 보존한다.

기준일: 2026-11-03. 사용자 요청 ‘검증시작해줘’에 따라 Windows Codex 데스크톱에서 실행했다. 이번 범위는 C 판정·집계·알림의 합성 입력 검증이다. 실제 영상 인식 정확도·의학적 효과·사람별 성능을 측정한 결과가 아니다. 판정 소스는 수정하지 않았다.

## 실행 결과

| 검증 묶음 | 실행 수 | 실제 결과 |
|---|---:|---|
| 기존 unittest | 8개 테스트 메서드 | 전체 통과, 종료 코드 0. 연속 깜빡임 메서드는 내부 9조건 포함 |
| 현재 규칙 확인 | 18개 시나리오 | 예상값·지정한 중간 시점 확인 모두 일치 |
| 한계 탐색 | 6개 시나리오 | 제안한 목표와 다른 결과 4개, 비교용 2개는 목표와 일치 |
| 무효 입력 안전 처리 점검 | 5개 시나리오 | 제안한 안전 기준과 모두 불일치 |

추가 시나리오는 총 29개다. 시나리오 수를 참가자 수·깜빡임 수·정확도 비율로 해석하지 않는다. `validate_scenarios.py`는 안전 기준 불일치를 반영해 종료 코드 **1**을 반환했다. 전체 통과라고 보고하지 않는다.

환경: Windows 11. `.venv` Python 3.13.9는 AMD64 64비트이며 gcc 타깃은 `x86_64-w64-mingw32`다. 실행 도구의 `PROCESSOR_ARCHITECTURE`는 ARM64로 표시됐다. 이전 문서의 ‘CPU AMD64’는 Python 관찰값이며 물리 CPU를 확정한 결과가 아니다. CIM 조회는 접근 불가였다. 설치나 아키텍처 전환은 하지 않았으며 이 Python과 DLL 조합에서 실제 실행에 성공했다.

WSL 조회는 다시 `Wsl/E_ACCESSDENIED`로 실패했다. Ubuntu·WSL 버전 및 Linux 테스트는 미확인이다. 이번 결과를 WSL 통과라고 쓰지 않는다.

## 가상 입력과 판정 기준

- 기본 입력: 열림 EAR 좌우 0.30, 감김 좌우 0.10, 입력 간격 33ms, 얼굴 검출 참. 별도 표기가 있으면 해당 값을 사용한다.
- 기본 설정: 감김 상한 0.18, 열림 하한 0.23, 동일 후보 상태 2프레임 확인. 횟수는 실제 경과 시간이 아닌 C의 유효 측정 시간 최근 60초 기준이다.
- 현재 규칙 확인은 기존 동작 계약과 비교한다. 긴 감김은 다시 열 때 1회, 한쪽 눈은 제외한다. 이 정책의 의학적 적절성은 이번 검증 대상이 아니다.
- 한계 탐색은 사용 목적상 원하는 결과와 현재 값을 비교한다. 합성 입력의 라벨만으로 실제 카메라 결함을 확정하지 않는다.
- 안전 점검의 제안 기준은 ‘NaN·무한대·음수처럼 유효하지 않은 EAR은 측정 시간·알림에 사용하지 않고, 무효 구간을 가로질러 깜빡임을 연결하지 않는다’다. 현 구현과 이 기준의 차이를 드러내며, 기대값을 현 결과에 맞춰 바꾸지 않았다.

## 합성 입력으로 확인한 한계

| 상황 | 비교 목표 | 실제 결과와 해석 |
|---|---|---|
| 양쪽 눈의 공동 감김이 1프레임뿐 | 시차가 있는 한 동작을 1회로 집계 | 0회. 공동 감김 2프레임 규칙으로 제외 |
| 40ms 감김 신호, 33ms 간격 샘플 | 합성 감김 1회 검출 | 0회. 해당 샘플 위상에서 감김이 1프레임뿐 |
| 같은 40ms 신호, 16ms 간격 샘플 | 합성 감김 1회 검출 | 1회. 두 프레임 확보. 사람의 정상 속도 또는 실제 FPS를 뜻하지 않음 |
| 열림 0.17·감김 0.08, 기본값 | 합성 동작 1회 검출 | 0회. 초기 OPEN을 확정할 수 없음 |
| 같은 값, 문턱값 0.10/0.15 | 합성 동작 1회 검출 | 1회. 합성 입력에 맞춘 비교용 설정이며 실제 권장값 아님 |
| A의 감긴 값 뒤 B의 열린 값이 연속 전달된다는 가정 | 두 사람 사이에서 깜빡임을 만들지 않음 | 1회. C 입력에 사람 ID가 없어 일반 깜빡임과 동일한 값이면 구분 불가 |

특히 ‘눈이 작은 사람은 작동하지 않는다’, ‘여러 명이 보이면 실제로 대상이 바뀌었다’는 결론을 내릴 수 없다. 각각 낮은 열림 EAR의 가정, 사람 구분 정보가 없는 인터페이스의 한계를 확인한 것이다. 웃음·시선·가림·고개 움직임도 동일한 EAR 신호를 만들면 C만으로 원인을 구분할 수 없다.

## 보완이 필요한 무효 EAR 처리

| 재현 ID | 제안 안전 기준 | 실제 결과 |
|---|---|---|
| invalid_nan | 유효 시간 0·알림 없음 | 유효 시간 60000ms·알림 발생 |
| invalid_inf | 유효 시간 0·알림 없음 | 유효 시간 60000ms·알림 발생 |
| invalid_negative | 유효 시간 0·알림 없음 | 유효 시간 60000ms·알림 발생 |
| invalid_nan_default_alert | 기본 설정에서도 무효 측정은 알림에 쓰지 않음 | 유효 시간 70000ms·70000ms에 알림 |
| invalid_mid_closure | 무효 구간 전후를 연결하지 않음 | OPEN→CLOSED→NaN→OPEN에서 1회 집계 |

원인: `be_update()`는 EAR 유효성을 검사하기 전에 `face_visible`로 유효 시간을 더한다. 무효 EAR에서 `eye_candidate()`가 UNKNOWN을 반환해도 기존 확정 상태는 유지되며 알림 조건 역시 `face_visible`만 확인한다.

현재 실행 경로의 `blink_app.py`는 얼굴 랜드마크 유무로 face를 정하고 EAR의 유한성 검사를 추가하지 않는다. 눈 가로 길이가 0이면 EAR 함수가 NaN을 반환할 수 있다. 따라서 방어 처리를 보완할 근거는 있으나 실제 웹캠에서 이런 좌표가 발생했는지와 빈도는 미측정이다. 미연결 `camera_worker.py`에는 유한성 검사 코드가 있으나 현재 앱에 적용됐다고 볼 수 없다.

다음 수정 후보는 무효 EAR을 미검출에 준해 처리해 시간 누적·상태 연결·알림을 막는 것이다. 음수·0·범위 밖 값까지의 유효성 정책과 C/Python 양쪽 책임을 정하고 이 재현 입력으로 수정 전후를 비교한다. 정상 EAR이 낮다는 이유만으로 무효 입력으로 취급해서는 안 된다.

## 실제 웹캠에서 남은 확인 — 모두 미측정

CSV·검증용 기록 기능을 연결한 뒤, 한 명·밝은 정면을 기본 조건으로 아래 항목을 하나씩 바꾼다. 수기와 검출 이벤트의 일대일 대응 허용 범위를 먼저 정한다. 총횟수뿐 아니라 잘못 센 것·놓친 것을 따로 기록한다.

| 항목 | 사용자가 할 동작 | 확인할 내용 |
|---|---|---|
| 자연스러운 깜빡임 | 평소처럼 화면 보기 | 수기 시점과 검출 시점 비교 |
| 한쪽 눈·연속 동작 | 좌우 한쪽 눈, 이어서 양쪽 연속 깜빡임 | 한쪽 제외·연속 동작별 집계 |
| 시선·표정·고개 | 키보드 보기, 웃기, 고개를 조금씩 돌리기 | 변화 전후 오탐·누락 |
| 가림·이탈 | 손으로 가리기, 자리 비우기·복귀 | 미검출 중 시간·알림, 복귀 직후 오집계 |
| 눈 모양 차이 | 참여 가능한 다른 사람도 같은 절차 수행 | 열린/감긴 EAR 분포·기본값 실패 여부 |
| 안경·밝기 | 가능한 조건을 하나씩 변경 | 좌표·EAR 변화와 오류 |
| 여러 사람 | 다른 사람이 옆에 들어오거나 뒤로 지나감 | 실제 측정 대상 전환 여부. 별도 실험으로 기록 |
| 처리 부하 | 다른 작업 중 같은 동작 비교 | 실제 FPS·누락·프레임 공백 |

## 재현 및 원본 근거

Windows에서는 현재 `.venv`의 Python으로 실행한다.

```powershell
.\.venv\Scripts\python.exe -m unittest test_engine.py -v
.\.venv\Scripts\python.exe validate_scenarios.py
```

첫 명령은 종료 코드 0, 두 번째는 현재 안전 점검 불일치로 1이다. Linux에서는 별도 가상환경·네이티브 `.so`를 준비해 같은 스크립트를 실행해야 한다. Linux에서 실행했다고 기록한 결과는 없다.

- [기존 테스트 실행 로그](unittest.log)
- [29개 시나리오 실행 로그](scenarios.log)
- [입력·출력 프레임 기록](synthetic_trace.csv)
- [예상값·관측값·불일치·소스 및 DLL 해시](synthetic_results.json)

보고서에 등장한 값은 위 실행에서 얻은 합성 입력 결과다. 사람의 측정값이나 임상 기준으로 사용하지 않는다. 사용자 기존 캡처는 MVP 기본 실행 확인 자료이며 이번 가상 검증과 구분한다.
