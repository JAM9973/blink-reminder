# 현재 실행 경로에 눈 좌표·CSV·FPS 기록을 연결했다

기준일: 2026-11-03. 실제 요청: ‘다음 구현 진행해줘’. 직전 합의한 눈 좌표·CSV·FPS 연결을 수행했다. Windows Codex 데스크톱에서 편집·자동 검증했다.

## 구현한 내용

| 항목 | 구현 |
|---|---|
| 눈 좌표 | 현재 blink_app.py의 EAR 계산에 사용하는 양쪽 6개씩 12개 점 표시. 기본 켜짐, L 키로 전환, --no-landmarks로 꺼서 시작 |
| FPS | 프레임 입력의 단조 시각 간격으로 약 최근 1초 평균 처리율 계산. 첫 프레임은 미정, 긴 공백도 반영. 설정 FPS·인식 정확도와 구분 |
| CSV | 기본 자동 기록, --no-csv로 중단, --csv-dir로 폴더 지정. data/records에 실행별 파일 생성 |
| 저장 값 | 프레임별 시각·FPS·입력 간격·실제 경과/유효 시간·검출/유효 여부·좌우 EAR·C 상태/이벤트/최근 횟수/알림·미달 시간·기준/문턱/프레임/대기 설정·좌표 표시 |
| 근거 보존 | 같은 이름의 JSON에 시작 설정·소스/DLL 해시·시간대 포함 시작 시각·FPS 정의 보존. 숫자만 저장, 얼굴 영상 저장 없음 |
| 오류·종료 | 약 1초마다 flush, 정상 종료·카메라 읽기 오류 시 close. 기록 시작/쓰기 오류는 화면 CSV: ERROR와 콘솔로 알리고 측정·알림 유지 |

별도 camera_worker.py의 좌표 표시·CSV 구조를 참고하되, 이번에는 기존 run.cmd → blink_app.py 경로에 필요한 부분만 연결했다. worker·설정창·일시정지·트레이·백그라운드 기능을 한꺼번에 연결하지 않았다. C·헤더·ctypes 브리지는 수정하지 않았으며 이전 수정 후 해시와 일치한다.

## 자동 검증

실행: `.\.venv\Scripts\python.exe -m unittest test_engine.py test_invalid_ear.py test_measurement_log.py -v`

결과: **22개 테스트 메서드 통과, 종료 코드 0**. 기존 15개에 기록·표시 연결 7개를 추가했다.

| 새 테스트 | 확인 결과 |
|---|---|
| FPS·긴 공백 | 33ms 간격의 FPS 계산, 첫 값 미정, 1901ms 공백 반영 |
| 좌표 변환 | 가로/세로 각각 변환, 프레임 밖 값 제한·비유한 좌표 제외 |
| 실제 앱 반복문+합성 입력 | 실제 C 엔진과 80개 합성 프레임으로 CSV 저장, 1회 검출·유효 60초 이후 알림, L 전환·+/- 기준 변경의 행별 기록 확인 |
| 미검출·무효 입력 | 미검출 EAR 빈칸, 무효 EAR 원값 nan, 별도 검출·유효 플래그, 해당 구간 유효 시간 유지 |
| CSV 끄기 | 파일 미생성, 측정·알림 유지 |
| 기록 시작/쓰기 실패 | 오류 뒤에도 측정·알림 진행. 쓰기 실패 시 기록기를 닫음 |
| 카메라 읽기 실패 | 앱 종료 경로에서 CSV 마지막 버퍼 행을 마무리해 읽을 수 있음 |

CSV의 UTF-8 BOM·한글 저장 경로·JSON 설정 및 소스 해시도 확인했다. Python 문법 검사·CLI --help·git diff --check 확인. 최초 테스트는 시스템 임시 폴더 ACL 문제로 신규 5개에서 PermissionError가 발생했다. 임시 테스트 자료를 프로젝트 .cache/measurement-tests의 독립 경로로 옮기고 정리 전 경로 경계를 확인하도록 바꾼 뒤 위 22개가 통과했다. 최종 결과만 남기고 처음 실패를 숨기지 않는다.

환경: Windows 11, Python 3.13.9 AMD64 64비트, gcc 타깃 x86_64-w64-mingw32, OpenCV 5.0.0·MediaPipe 1.0.1. WSL 조회는 E_ACCESSDENIED로 실패해 Ubuntu·Linux 실행은 미검증이다. 의존성 설치·Git 커밋·태그·원격 변경 없음.

## 근거와 해석 범위

- [자동 검증 결과 요약·소스 해시](automated_check_summary.json)는 실제 실행에서 확인한 결과의 요약이다. 원본 터미널 전체 로그 파일은 아니다.
- synthetic_example 폴더의 CSV·JSON은 실제 C에 별도 합성 입력 10행을 넣어 생성한 기록 파일이다. `input_kind=synthetic`과 합성 시각 라벨을 명시했다. 1회 검출·미검출·무효 EAR 행이 저장됐다. 사용자 웹캠 측정 자료로 사용하지 않는다.
- 실제 영상의 눈 좌표 추적·FPS 수치·수기 대비 오탐/누락·빠른 두 번 합산 원인은 이번에 측정하지 않았다. 실제 웹캠을 열거나 GUI를 조작하지 않았다.
- 이번 구현으로 무효 EAR 보완과 기존 C 판정 규칙을 바꾸지 않았다. 빠른 동작·낮은 열림 EAR·사람 대상 전환의 기존 한계는 남아 있다.

## 사용자가 확인할 절차 — 현재 미확인

1. 실행 중인 기존 앱을 Q로 종료하고 프로젝트의 run.cmd를 다시 실행한다.
2. 눈 주변 점이 눈을 따라 움직이고 FPS 숫자·CSV: ON이 표시되는지 확인한다. L 키로 점을 숨기고 다시 켠다.
3. 평소 깜빡임, 빠른 두 번, 얼굴 미검출·복귀를 짧게 수행한다. 이 단계는 파일 저장 확인이며 정식 정확도 실험은 아니다.
4. Q로 종료한 뒤 data/records에 이번 실행의 CSV와 같은 이름의 JSON이 생겼는지 확인한다. CSV에 여러 행·blink 이벤트·미검출 행이 있는지 본다.
5. 화면 또는 저장 오류가 있으면 메시지와 실제 생성 파일을 기준으로 수정한다. 이 기본 확인을 마치면 실험 조건과 수기 시점 대응 규칙을 정해 비교한다.

종료 후 CSV를 분석할 때는 최근 60초 총횟수만 보지 않고 blink=1인 이벤트 행을 비교한다. 로그만으로 실제 사람이 깜빡인 정답 시점을 자동 확정할 수는 없으므로, 오탐·누락 산출에는 대응되는 수기 기록이 필요하다.
