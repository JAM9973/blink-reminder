# 무효 EAR의 시간 누적·상태 연결·알림 문제가 재검증에서 해결됐다

기준일: 2026-11-03. 실제 요청: ‘무효 EAR 처리 보완하고, 기존 테스트와 실패했던 가상 입력을 다시 검증해줘.’ Windows Codex 데스크톱에서 수정·검증했다. 실제 웹캠 재실행은 아직 하지 않았다.

## 변경한 규칙

- 양쪽 EAR이 모두 유한한 비음수일 때만 유효 측정으로 처리한다. NaN·양/음의 무한대·음수는 한쪽에만 있어도 측정을 일시 중단한다.
- EAR 0은 눈이 완전히 감긴 유효 입력으로 유지한다. 낮지만 유효한 EAR에 임의의 최소값이나 상한을 추가하지 않았다.
- 무효 입력은 얼굴 미검출과 같은 경로로 처리해 눈 상태·후보 상태를 초기화하고, 유효 시간·횟수·알림을 진행하지 않는다. 무효 입력 직후 복귀한 첫 프레임까지의 시간차도 누적하지 않는다.
- 이전에 정상 집계한 기록과 알림 대기·재알림 시계는 보존한다. 유효 측정 시간 기준으로 다시 진행하며 기존 60초 만료 규칙을 따른다.
- 복귀 후 OPEN 상태를 다시 확인해야 새 깜빡임을 센다. 감긴 상태로 복귀한 뒤 처음 뜨는 동작은 세지 않는다.

## 코드 변경

| blink_engine.c | 시간 누적·눈 상태·알림 처리 전에 EAR 유효성을 적용. 무효 입력을 미검출 경로로 전달 |
| blink_engine.h / engine.py | 반환 face_visible이 유효 관측 여부라는 의미와 무효 입력 정책 문서화. 함수 인자·구조체 배치는 유지 |
| blink_app.py | C 호출 전에 유효성 확인, 얼굴이 있으나 EAR이 무효인 경우 INVALID EAR 표시 |
| camera_worker.py | 미연결 확장 모듈도 음수 제외 기준을 일치시킴. 이번에 앱과 연결하지 않음 |
| test_invalid_ear.py | 무효 입력·정상 복귀·기존 기록·알림 시계·0/낮은 EAR·퇴화 좌표 회귀 테스트 7개 추가 |
| validate_scenarios.py | 이전 결과를 보존할 수 있도록 --output-dir 추가, 테스트·확장 소스 해시 포함. 기존 29개 입력·기대값·설정은 유지 |

## 수정 전후 같은 입력으로 비교

기존 29개 시나리오의 **1,399개 입력 행**(시나리오·시각·좌우 EAR·얼굴 검출)을 수정 전후 비교해 일치함을 확인했다. 기대값과 시나리오별 설정도 동일하다. 정상 규칙 18개의 관측 결과는 모두 동일하다.

| 이전에 실패한 입력 | 수정 전 | 수정 후 |
|---|---|---|
| NaN EAR 60초, 미달 대기 0초 | 유효 시간 60000ms, 알림 발생 | 유효 시간 0ms, 알림 없음 |
| 무한대 EAR 60초, 미달 대기 0초 | 유효 시간 60000ms, 알림 발생 | 유효 시간 0ms, 알림 없음 |
| 음수 EAR 60초, 미달 대기 0초 | 유효 시간 60000ms, 알림 발생 | 유효 시간 0ms, 알림 없음 |
| NaN EAR 70초, 기본 알림 설정 | 유효 시간 70000ms, 알림 발생 | 유효 시간 0ms, 알림 없음 |
| OPEN → CLOSED → NaN → OPEN | 1회 집계 | 0회 집계 |

## 실행 결과와 의미

| 묶음 | 수정 전 | 수정 후 |
|---|---|---|
| 기존 unittest 8개 | 통과 | 통과 |
| 신규 회귀 테스트 7개 | 5개 메서드에서 실패, 2개 통과. 서브테스트 포함 실패 13건 | 7개 모두 통과 |
| 정상 규칙 시나리오 18개 | 기대값 일치 | 동일 결과 유지 |
| 무효 입력 안전 점검 5개 | 모두 기대값 불일치 | 모두 기대값 일치 |
| 한계 탐색 시나리오 6개 | 4개는 목표와 차이, 2개 비교 사례는 일치 | 같은 결과 유지 |

최종 unittest는 **총 15개 통과·종료 코드 0**이다. 시나리오 실행은 **29개 실행·정상 규칙 실패 0·안전 점검 실패 0·종료 코드 0**이다. 남아 있는 한계 탐색 4개를 해결했다고 해석하지 않는다.

추가 회귀 테스트는 한쪽 EAR만 잘못된 경우, NaN·양/음의 무한대·음수, 무효 구간 전후의 상태 단절, 기존 기록 보존, 복귀 후 새 깜빡임 집계, 미달 대기·재알림 시간 일시 중단을 포함한다. 0 EAR과 낮은 유효 EAR은 정상 처리됨을 확인했다. 퇴화한 합성 눈 좌표로 Python EAR 함수가 NaN을 반환하는 경로도 C와 함께 확인했다. 실제 얼굴에서 이 좌표가 발생했다는 뜻은 아니다.

Python 변경 파일 문법 검사와 소스 해시·이전 스냅샷·입력 행 비교도 확인했다. 최초 회귀 테스트 구성에서 같은 Windows 프로세스가 로드한 DLL을 다시 빌드하려다 Permission denied가 발생했다. 신규 테스트 클래스의 중복 빌드를 제거한 뒤 동일 회귀 검증을 실행했으며, 이 초기 도구 구성 실패도 별도 로그로 보존했다.

## 사용자 Windows 확인 — 현재 미수행

기존 실행 중인 앱이 있으면 Q로 종료하고 run.cmd를 다시 실행한다. 이미 실행 중인 프로세스에는 새 DLL이 적용되지 않는다.

1. 평소 속도로 깜빡여 감지·집계가 계속되는지 확인한다.
2. 얼굴을 가리면 NO FACE가 표시되고 Observed 시간이 멈추는지 확인한다. 얼굴을 다시 보였을 때 복귀 자체로 횟수가 늘지 않는지 본다.
3. 알림 확인은 기존처럼 기준을 최근 횟수보다 높이고 유효 측정 60초 이후 기준 미달이 10초 유지될 때 팝업이 나오는지 확인한다. 확인 후 기준을 원래 값으로 되돌린다.

무효 EAR을 사람이 일부러 만들어낼 필요는 없다. 해당 처리는 가상 입력으로 확인했다. 수정 후 자연스러운 깜빡임·알림의 실제 동작은 사용자가 실행한 결과를 받아 별도로 기록한다.
